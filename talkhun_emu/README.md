# TALKHUN under emulation

The real 1991 BraiLab talker (`TALKHUN0.COM`, 45,301 bytes, dated 1991-11-28)
running under the Unicorn CPU emulator, with its printer-port link to the
PCF-8200 speech chip captured instead of played.

Modelled on the Dr. Sbaitso / SmoothTalker addon (a sibling checkout), which runs
the 1990 First Byte engine the same way.

## A software PCF-8200 — the speech chip MAME never emulated

The PCF-8200 is a Philips formant speech synthesizer, and it was the final-stage
silicon under a whole early-1990s generation of speech systems for blind computer
users: in Hungary the BraiLab PC adapter and the PC-ROBOT / MULTIVOX card, in
Barcelona the **Ciber232** system (Llisterri, Fernández, Gudayol, Poyatos & Martí,
ESCA Workshop on Speech Technology for Disabled Persons, Stockholm 1993). Each
shipped its own diphone data; the chip turned the codes into a voice.

MAME emulates the PCF-8200's older four-formant sibling, the MEA-8000 — it rides
inside the Thomson home computers and the Hungarian Homelab — but never the
PCF-8200 itself, because the PCF-8200 only ever lived in PC add-on cards for the
blind, which MAME does not collect. This project fills that gap: `synth.py`
extends the MEA-8000 model to the PCF-8200's five-formant design with the chip's
real code-expansion tables (`pcf8200_tables.py`), so one emulator can drive
anything that ever spoke through the chip. TALKHUN0 is the first such driver
brought back to life; the same decoder reads the PCF-8200's byte protocol
whatever the source.

## Why there is no engine image to build

Sbaitso needs a captured `engine.bin` because SBTALKER is a TSR whose far
pointers are baked into one particular conventional-memory layout — you have to
snapshot live DOS memory with it already resident.

TALKHUN0 needs nothing of the sort. It is a flat `.COM`: load it at `seg:0x100`,
give it a PSP, and run its own installer with DOS shimmed. The installer hooks
INT 14h and calls `AX=3100` (TSR); we stop there, and what is left in emulator
memory *is* the resident engine — generated by the original 1991 installer
rather than captured from a machine.

Nothing needs to be extracted, patched or reimplemented. The ESC parser,
intonation arithmetic, diad lookups and frame generation are all the original
code doing its original work.

One constraint on the load address: the installer's already-resident check walks
*every* segment below CS comparing 16 bytes, so `PROG_SEG` wants to stay modest.
`0x0800` is fine; moving it up to a high segment turns that scan into a long
stall for no benefit.

## The interface

Recovered from the install stub at `0xb146` and the handler at `0x1168`:

| call | effect |
|---|---|
| `INT 14h  DL=3  AH=0` | reset settings to the engine's defaults |
| `INT 14h  DL=3  AH=1  AL=c` | feed one character to the ESC parser at `0x121b` |
| `INT 14h  DL=3  AH=3` | status, returns `AX=0x30` |
| any other `DL` | chains to the saved original vector |

`DL=3` is COM4 — this is the "virtual COM device" `HALLGASD.MEG` describes, and
why `COPY FURCSABE COM4` spoke on a real machine. DOS's COM driver calls INT 14h
per character.

The LPT base lives at `[0x1da3]`, defaults to `0x378`, autodetects from the BIOS
data area at `0040:0008`, and can be overridden with a `,XXX` hex command tail.

The engine is **line buffered**: characters accumulate until an intonation-unit
delimiter (`.` `,` `;` `:` `?` `!`) arrives. Text with no delimiter emits
nothing at all. `synthesize()` appends one when needed.

## The adapter link

A 2-wire bit-bang over the printer port, no register addressing:

```
0x1e40  out base+0 <- (clock<<1)|data ;  out base+2 <- same ^ 2
0x1e2b  one bit taken from CF, clocked low / high / low
0x1df8  stc; rcl bl,1  puts a sentinel at the bottom so the loop runs
        exactly 8 bits MSB first, then an explicit stop bit
0x1df0  preamble + a 0x20 frame marker      0x1e1c  postamble
```

A transaction is `preamble, 0x20, payload…, postamble`. Five payload bytes are a
speech frame; two (`0x00` then the command) are a control write.

### The handshake, which is the one real trap

The ready poll at `0x1dc4` returns CF=0 when status bit 4 is clear, and CF=1
when bit 4 is set with bit 5 clear. **The callers do not agree on polarity**:
the utterance-start control write at `0x1d2c` proceeds only on CF=1, while every
poll after it wants CF=0.

Physically that is an adapter whose busy line rests high and drops once
addressed, so `Talkhun` reports busy for the first poll of an utterance and
ready from then on.

Getting this wrong fails **silently**: with a plain "always ready" status the
engine still emits every speech frame, but the start control write — the one
carrying furcsa and tempo — is skipped and you never see it.

## Frames and control writes

Frame layout (datasheet p5 / Fig. 4) and the control format (Fig. 5) are
implemented in `pcf8200.py`. By default the formant frequencies and bandwidths
are the chip's own quantization tables (`pcf8200_tables.py`); `render(real=False)`
selects MAME's MEA-8000 tables plus our earlier reconstructions instead, for
comparison. Either way the codes are **indexed directly** — an earlier +1 offset
turned out to be a cross-dataset artifact (thesis codes describe TALKHUN0's diad
data but were calibrated against TTS.dll audio, which speaks BINADATA, a
different authoring). Settled by ear against the original hardware; one table
step is ~6% and the +1 renders were consistently heard as "slightly furcsa".

Speed: the engine's own default is S2 (100%), but the archive's `BRAISET.DAT`
and `DEFAULT` both set `ESC S6`, which pins the chip to its fastest hardware
rate — the same FS bits as S4 — plus software acceleration. The household
BraiLab ran at the S4 chip rate, confirmed independently by ear, so the demo
renders use `--speed=4`.

## What it produces

`mama.` yields 41 frames, 525 ms nominal, plus `00 80` (start) and `00 a0`
(stop). Decoded:

```
 13  75 be 5b 6d e3   F1=21  F2=13  ->  622 Hz   988 Hz
```

Codec `F1=21, F2=13` is exactly what Arató's thesis records for /a/, and the +1
offset maps it to 622/988 Hz against **625/988 Hz measured by LPC from real
BraiLab hardware audio** — 3 Hz error on F1, zero on F2. Frames 28–33 come back
byte-identical to 11–16: the diad database reusing the same vowel.

The ESC layer is fully live, verified against the engine's own memory:

| fed | effect |
|---|---|
| `ESC` | parser state → `0xFF` |
| `ESC F 1` | settings `0x70` → `0x78` (bit 3), control byte `00 80` → **`00 90`** |
| `ESC P 70` | pitch byte `0x2a` → `0x46` |
| `ESC S 4` | tempo bits → 1, control byte → `00 81` (FS=01, 145%) |
| `ESC S 1` | tempo bits → 3, control byte → `00 83` (FS=11, 73%) |

The S1→3, S2→0, S3→2, S4→1 mapping matches the datasheet's FS table and
`EFFECTS.DOC`'s narration ("leglassúbb" at S1, "leggyorsabb" at S4).

**Furcsa hang is reachable again.** The 2021 `TTS.dll` reimplementation dropped
the whole ESC layer, so the attribute voice that marked inverse-video text had
no way to be switched on. Here the original parser sets the bit and the original
transmit path ships it.

## The software chip (`synth.py`)

Ported from MAME's `mea8000.cpp`. Excitation is a sawtooth at F0, or noise when
`PI == 16`; it is scaled by the frame amplitude and run through a cascade of
second-order resonators, one per formant, with every parameter interpolated
across the frame.

Synthesis runs at **8× the chip rate (80 kHz) and is decimated**. A sawtooth
generated directly at 10 kHz is not band-limited, so every harmonic above 5 kHz
folds back into the speech band as inharmonic hash — 31.8% of the output energy
sat above 3 kHz, audible as the render being brighter and harsher than BraiLab.
After oversampling that is 0.0%, and the spectral centroid drops from 2409 Hz to
644 Hz. 80 kHz is not arbitrary: it is the rate the datasheet says the chip
upsamples its own output to.

Resonators are **Klatt-normalised to unity DC gain** (`a0 = 1 - b1 - b2`). MAME
omits that term, which is fine at one fixed rate but not across rates: without
it a stage's gain goes as ~1/(1−r)² at low frequencies and r → 1 as the rate
rises, so oversampling silently rebalances the cascade toward the low formants.
At 8× that buried F3 completely — the /a/ lost its third formant, 2842 Hz simply
absent from the spectrum. With DC normalisation it comes back at 2850 Hz.

(Normalising at the resonance peak instead is worse than either: the scalar then
jumps between interpolation blocks, desynchronising the filter's retained state
and smearing the formants — LPC on that version read F1 804 / F2 2864 where it
should read 625 / 990.)

**Output rate.** The chip runs at 10 kHz and `render()` stays there, but
`write_wav()` resamples to 22050 Hz. This is not cosmetic: a valid 10 kHz WAV —
correct header, correct data, verified peak and spectrum — played as **silence**
on the first listening test. The sbaitso addon resamples for the same reason and
says so in its own comment ("8475 Hz, which not every output path accepts").
Resampling costs nothing here, since the chip band-limits to 5 kHz anyway; after
conversion only 0.30% of the energy sits above 5 kHz.

Output is **RMS-normalised per utterance**, not peak-normalised. A cascade's
overall gain depends on formant position — `/u/`, with F1 and F2 both low, loses
far more through the upper resonators than `/i/` does — so raw level swings
about 30 dB between utterances. A screen reader needs consistent *loudness*,
which means matching RMS. Across a mixed corpus this holds speech RMS at 4000
with peaks around 19–28k and no clipping.

**Pitch is not in the frames.** The frame's `PI` field is only an increment; the
absolute value arrives as a separate one-byte transaction at utterance start —
MEA-8000's pitch register, which is why the frame/control filter originally
missed it. It tracks `ESC P` with a constant +4 offset:

| `ESC P` | on the wire |
|---|---|
| 42 (default `*`) | 46 |
| 20 | 24 |
| 70 | 74 |
| 100 | 104 |

The chip's start-pitch byte is `Hz × 0.4096`, i.e. **2.44 Hz per unit**, so the
default 46 units ≈ 112 Hz at onset (the `real=False` fallback keeps MAME's
2 Hz/unit at 8 kHz scaled to 2.5 at 10 kHz, ≈ 115 Hz). Pitch declines through the
utterance via the `PI` decrements — which is exactly what `HALLGASD.MEG` means
by calling `P` the *initial* pitch ("kezdeti alaphang magasság") with intonation
deviating from it.

The default tables in `pcf8200_tables.py` are the chip's own code-expansion
values — the full five-formant male and four-formant female ladders, distinct
bandwidth ladders per formant (code 0 = 3000 Hz = "formant off"), the amplitude
and pitch-increment tables. The fallback set (`real=False`) still carries the
values marked RECONSTRUCTED in the source, from before those tables were
available: the PCF-8200's bandwidth field is 3-bit where MAME's is 2-bit, and
MAME has no F4/F5, so those were geometric fits anchored on the four bandwidths
MAME confirms and on the F4 ≈ 3300–3390 Hz seen across the Hungarian vowels in
the LPC work. The real tables replace all of that with the chip's actual values.

### Does it sound like BraiLab?

Rendered `mama.` analysed with the same order-12 LPC used on the real hardware
captures:

```
 0.170   F0 109   F1 625   F2 992     real BraiLab /a/:  F0 108  F1 625  F2 988
 0.180   F0 108   F1 630   F2 980
```

The whole trace has the right shape for "mama": /m/ at F1≈333 F2≈1500, /a/ at
625/990, /m/ again, /a/ again. F0 enters around 112–116 Hz — the 46 pitch units
× the ~2.4–2.5 Hz/unit derived above — and declines across the utterance, as
`ESC P` being only the *initial* pitch implies.

Voicing is right too: `mama.` produces 0 unvoiced frames, `szia.` 12 and
`sas.` 23, the `PI=16` noise flag landing exactly on the Hungarian fricatives.

## Two synthesizers

`synth.py` is the main synthesizer, and with the chip's real tables
(`pcf8200_tables.py`) it renders the default voice. `mame_synth.py` follows
MAME's `mea8000.cpp` signal path instead; back when `synth.py` still ran on the
reconstructed tables `mame_synth` was the cleaner of the two by ear, and it
stays as a MEA-8000-faithful comparison. It exists because MAME's MEA-8000 is
a *validated* emulation of the chip BraiLab 4 actually contained (the homelab
driver instantiates `MEA8000(config, "mea8000", 3'840'000)`, credited to the
same Lukacs brothers who built the BraiLab PC's adapter), so its structure is
evidence rather than guesswork:

  * filters run **at the chip rate** with the output linearly interpolated x8 --
    not oversampled synthesis
  * resonators **unscaled**, which is safe only because the rate never changes
  * four formants, the fourth **fixed at 3500 Hz**

## Calibrated by ear, not by metric

Several settings here were chosen against Tomi's memory of the real machine
after a spectral measurement pointed the other way. Recording them because the
measurements are still in the repo and look persuasive:

| setting | metric said | ear said |
|---|---|---|
| `BW_SCALE` | widen for flatness | 1.0 -- widening smears formants together |
| `CABINET_HZ` | 150 Hz halves band error | off -- "gives it more of a chest" |
| `NOISE_GAIN` | ratio saturates below 0.35 | 0.25, and 0.50 was *more* stabby |
| `MALE_FORMANTS` | 4 (log-spectral distance) | 5 -- LSD measured the wrong thing |
| `CODEC_OFFSET` | +1 from thesis values | 0 -- +1 read as "slightly furcsa" |

The pattern is consistent enough to be a rule: when a band metric and the ear
disagree, the ear wins. The metrics are useful for finding *bugs* (a 40% pitch
sag, fricatives at twice the right level) and misleading for choosing *taste*.

## Running it

```
pip install unicorn
python demo.py  "mama."                 # dump frames
python speak.py "mama." mama.wav        # render audio
python speak.py "mama." f.wav --furcsa
python speak.py "szia." s.wav --speed=4 --pitch=70
```

Needs `TALKHUN0.COM` in `../BRAILAB-archive/`.

## Not done yet

- **NVDA driver.** Clone the sbaitso shell (`smoothtalker.py`): worker thread,
  generation-numbered cancellation, streamed feed to nvwave. No 32-bit bridge is
  needed — unlike the TTS.dll path, this is pure Python and runs native in
  64-bit NVDA.
- **The female table — resolved.** For a long time the female (furcsa) Hz values
  weren't available, and they can't be recovered from the archive: `BINADATA.BIN`,
  `BINAHANK.BIN` and every talker binary were searched, and **the known *male*
  table isn't in them either** — the host only ever ships 5-bit codes down the
  wire and the silicon does the lookup. In the meantime furcsa was reconstructed
  from physics (a female vocal tract is ~15–20% shorter, so `FEMALE_SCALE` = 1.18
  shifted the male formants up; still available under `real=False` via
  `--female-scale=N`). The chip's real four-formant female table is now the
  default, and it's a clear step up by ear — furcsa finally sounds like furcsa.

## Calibrating against the real engine

`TTS.dll` — the 2021 reimplementation this repo's wrapper drives — is the only
reference recording available, and it can be captured on demand: a 32-bit
`brailab_wrapper.dll` rig speaks a phrase and returns raw 10 kHz PCM. That makes
A/B measurement possible rather than guesswork, and it caught a defect no amount
of frame-level checking would have.

The emulator originally carried **23× the real engine's energy above 2 kHz**,
heard as a "squished headsize" — a head too small for the voice. Two causes,
found by sweeping each against the reference spectrum:

1. **Source spectrum.** A raw sawtooth's harmonics fall at −6 dB/octave; a real
   glottal source falls at about −12, and the chip filters further. Added a
   one-pole tilt on the *voiced* excitation only (`SOURCE_TILT_HZ` = 800) —
   frication really is broadband, and rolling it off would dull the sibilants.
2. **The invented fifth formant.** `F5_TAB` has no documentary basis, and it was
   piling energy into 3–4 kHz where the real engine has essentially none.
   Log-spectral distance to the reference: **11.99 dB with F5, 8.49 dB without.**

Above 2 kHz the emulator now sits at 1.9× the real engine rather than 23×, and
`mama.`'s spectral centroid fell from 2409 Hz (pre-oversampling) to 520 Hz.

Note the tension worth being honest about: the datasheet says five formants for
male speech, and the frame *does* carry an F5 bit, which is decoded. But a
guessed resonator measurably beats no resonator only when the guess is right,
and this one is not — so `MALE_FORMANTS` is 4. Set it to 5 if the real table
ever surfaces.

same phrase, for direct comparison.
